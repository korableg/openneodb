# Формат Neoline DB

Каталог содержит нормализованную запись `CameraRecord` и
`NeolineDBWriter`. Production-код этого модуля только формирует бинарную базу
и не читает готовые Neoline DB.

## Заголовок

Полный размер файла равен `0x440 + N × 24`, а длина полезной нагрузки в
`0x107` — `0x40 + N × 24`.

| Смещение | Размер | Содержимое |
| --- | --- | --- |
| `0x000` | 5 | ASCII `BRMSC` |
| `0x005` | 2 | нули |
| `0x007` | 5 | ASCII `JHKIM` |
| `0x00C` | 244 | нули |
| `0x100` | 7 | `24 00 02 00 00 00 00` |
| `0x107` | 4 | `0x40 + N × 24`, `uint32 little-endian` |
| `0x10B` | 245 | нули |
| `0x200` | 512 | внутреннее имя ASCIIZ, остаток заполнен нулями |

У 9000c внутреннее имя может быть полностью пустым; RevM60 его не читает.
Writer всегда пишет `https://github.com/korableg/openneodb`.

## Метаданные и записи

| Смещение | Размер | Содержимое |
| --- | --- | --- |
| `0x400` | 16 | `FF` |
| `0x410` | 8 | дата `DDMMYY` и два нуля |
| `0x418` | 8 | `FF` |
| `0x420` | 4 | `32 44 F8 39` |
| `0x424` | 3 | `00 01 01` |
| `0x427` | 9 | `FF` |
| `0x430` | 4 | число записей, `uint32 little-endian` |
| `0x434` | 12 | `FF` |
| `0x440` | `24 × N` | записи |

Записи стабильно сортируются по убыванию широты, сохраняя исходный порядок
при одинаковой широте. Два направления одной камеры обычно кодируются парой
записей с одинаковыми координатами и азимутами, отличающимися примерно на
180°. Запись с индексом `i` расположена по адресу `0x440 + 24 × i`.

Файл не должен превышать `0x300000` байт, поэтому допустимо не более
131 026 записей.

## Структура записи

Многобайтовые числа имеют порядок `big-endian`. Перед записью каждый байт
открытой 24-байтной записи XOR-ится с соответствующим байтом ключа:

```text
A3 AE CB 2C 7D 99 80 46 4A 00 13 AD 8A 3A 56 3C 0C 5A 08 73 3B 6F EF 78
```

| Смещение | Размер | Содержимое |
| --- | --- | --- |
| `+0` | 1 | тип объекта, `uint8` |
| `+1` | 4 | широта: `floor(latitude × 10000)`, `uint32` |
| `+5` | 4 | долгота: `floor(longitude × 10000)`, `uint32` |
| `+9` | 2 | направление движения, `0`…`359`, `uint16` |
| `+11` | 1 | направленность: `0` все, `1` одно, `2` оба направления |
| `+12` | 1 | ограничение скорости, км/ч; `0` — не задано |
| `+13` | 4 | широта второй точки: `floor(latitude × 10000)` или `0` |
| `+17` | 4 | долгота второй точки: `floor(longitude × 10000)` или `0` |
| `+21` | 1 | флаги; `0x02` коррелирует с безрадарным комплексом, `0x20` встречается у круговых камер в вендорском формате |
| `+22` | 1 | допуск по курсу; `1`…`45`, иначе прошивка использует 20° |
| `+23` | 1 | дистанция в декаметрах; `0` означает значение прошивки |

Дистанции меньше 100 м прошивка поднимает до 100 м, значения больше 2000 м
сбрасывает к 500 м. Нулевой допуск и значения больше 45° прошивка заменяет
на 20°.

Круговые камеры кодируются двумя известными способами. Для RevM60 следует
использовать `direction_type = 0`. Вендорский шаблон для новых прошивок
использует `direction_type = 1`, `flags |= 0x20`, `tolerance = 5`. RevM60
передаёт дальше только `flags & 0x1F`, поэтому биты `0x20`, `0x40` и `0x80`
не влияют на его обработку.

## Типы объектов

| Тип | Байты в файле | Назначение |
| --- | --- | --- |
| `0x01` | `A2` | Стрелка |
| `0x04` | `A7` | участок средней скорости со второй точкой |
| `0x06` | `A5` | стационарный радар |
| `0x07` | `A4` | пост ДПС |
| `0x0B` | `A8` | муляж камеры |
| `0x0C` | `AF` | Стрелка без радарного модуля |
| `0x2B`, `0x2C` | `88`, `8F` | подтипы стационарного радара |
| `0x4A` | `E9` | контроль средней скорости без второй точки |
| `0x4C` | `EF` | специальный тип: скорость принудительно 0, дистанция 200 м, оповещение только при скорости не менее 20 км/ч |
| `0x29`…`0x50`, прочие | `тип XOR 0xA3` | обобщённая камера |
| `0x00`, `0x02`, `0x03`, `0x05`, `0x08`…`0x0A` | `A3`, `A1`, `A0`, `A6`, `AB`, `AA`, `A9` | неактивные типы, оповещение не выдаётся |
